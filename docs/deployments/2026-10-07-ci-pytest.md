## Context

#15 reached `master` with ten commits pushed by `/apply` and `/apply all`.
Four broke it: a type hint importing a non-existent `RepoRef` (the app could
not start), a "fixed" test fixture (3 failing tests), a test calling `.id`
on a string, and four line-ending tests deleted to satisfy a naming rule.
`/apply` relies on "the repository's CI tests the pushed commit", but this
repo's CI only ran the AI review. Repaired in #19; this adds the missing
test run so it cannot recur silently.

## What changed

- `.github/workflows/pr-pipeline.yml` — new `tests` job beside `review`:
  checkout, Python 3.12 with pip caching on `pyproject.toml`,
  `pip install -e . pytest pytest-asyncio`, `pytest -q`. Actions pinned to
  commit SHAs (`actions/checkout` v4.4.0, `actions/setup-python` v5.6.0).
  Runs on drafts too; shares the workflow's per-PR concurrency group.
- `CLAUDE.md` — Testing section says CI runs the suite.
- Not added to `pipelines/github/pr-review.yml` (the template other repos
  copy): their test commands differ.

## Design decisions

- Python 3.12, matching the dev container. 3.11 (the `requires-python`
  minimum) could not be rehearsed here (`python3.11-venv` missing), so it is
  not in CI yet.
- `pip install -e .` resolves current versions (there is no lock file), so CI
  also catches a dependency release that breaks the suite.
- `/apply` pushes use `PR_REVIEW_APPLY_TOKEN`, so they fire `synchronize`
  and this job runs on bot commits too.
